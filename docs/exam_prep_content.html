Частина 1. Питання, які може задати викладач по коду

Проєкт: «Нічний Дозор» — tower defense, 11 скриптів у Assets/Scripts/

1. Загальна архітектура

П: З чого складається гра?
О: TDGameBootstrap (запуск), GameManager (логіка), GameConfig (числа), UIManager (інтерфейс), TowerInput (миша), Tower, Enemy, Projectile, LevelMap, BuildZone, ModelSpawner.

П: Як гра запускається?
О: У TDGameBootstrap метод з [RuntimeInitializeOnLoadMethod] після завантаження сцени створює NightWatchGame і додає GameManager, UIManager, TowerInput.

П: Де «мозок» гри?
О: GameManager — золото, хвилі, будівництво, HP кристала, спавн, перемога/поразка.

П: Де всі числа балансу?
О: GameConfig.cs — константи та методи розрахунку статів.

2. Unity: Awake, Start, Update

МетодКолиУ проєкті
AwakeОдин раз при створенніGameManager.Instance = singleton
StartПеред першим кадромМеню, WarmUp моделей
UpdateКожен кадрТаймер, HUD, атака башен, рух ворогів

П: Що таке MonoBehaviour?
О: Базовий клас Unity-скрипта на об'єкті сцени; дає Start/Update, transform, Destroy тощо.

3. Патерни

П: Singleton?
О: GameManager.Instance — один менеджер на всю гру. У Awake: якщо вже є — Destroy.

П: Навіщо static class GameConfig?
О: Налаштування без об'єкта в сцені — один джерело балансу.

П: enum у проєкті?
О: RaceType, TowerType, EnemyType, Difficulty, WaveRewardType — списки варіантів.

4. GameManager

П: Як ставиться башня?
О: TowerInput → клік → FindBuildZoneFromScreen → TryBuildAtZone → new GameObject + Tower.Init().

П: Коли хвиля пройдена?
О: WaveActive, _spawnDone, ActiveEnemies.Count == 0 → OnWaveComplete().

П: Де HP кристала?
О: CrystalHp, CrystalMaxHp у GameManager; урон через DamageCrystal().

П: Що після закінчення часу хвилі?
О: WaveOvertime = true; кристал отримує 2 HP/с, поки ворогів не знищать.

П: Нагорода після 4-ї хвилі?
О: OnWaveComplete → OfferMilestoneReward → 3 випадкові бонуси з 9 (WaveRewardConfig.PickRandomOffers).

5. Корутини

П: Навіщо IEnumerator і yield return?
О: SpawnWave спавнить ворогів з паузами (WaitForSeconds), не блокуючи гру. Башні й UI працюють далі.

6. LevelMap і BFS

П: Як вороги знають шлях?
О: BuildWorldWaypoints → масив Vector3; ворог рухається _path[_wp] → _path[_wp+1]...

П: Що таке BFS?
О: Пошук в ширину в FindPath — черга, сусіди по 4 напрямках, тільки клітинки дороги до кристала.

П: Де можна будувати?
О: IsBuildable — не дорога, не дерево, не кристал, не край; BuildZone на таких клітинках.

7. Tower, Enemy, Projectile

П: Як башня обирає ціль?
О: FindBestTarget — найближчий живий ворог у радіусі Combat.Range.

П: Типи атак?
О: Single, Aoe (мортира), Slow (freeze), Chain (блискавка, 3 цілі).

П: Ворог дійшов до кінця?
О: ReachCrystal → DamageCrystal, Destroy.

П: Особливість боса?
О: 10-а хвиля, багато HP, SpawnBossMinion кожні 3.5 с.

8. Механіки екзамену (RANDOM.ORG)

МеханікаДе в коді
Стартовий вибір (складність + раса)BuildMenu, SelectRace, DifficultyConfig, RaceRate/Damage/Gold
Часові обмеженняGetWaveTimeLimit, TickWaveTimer, overtime 2 HP/с
Захист ціліCrystalHp, SpawnPaths, програш при 0 HP
Нагорода після 4-ї хвиліWaveRewardConfig, 3 з 9 випадкових

9. Каверзні питання

  • Без EventSystem — кнопки UI не клікаються.
  • Ворог не йде напряму — тільки по BFS-шляху по дорозі.
  • Продаж — 70% (SellRefundRate = 0.7).
  • ActiveEnemies.RemoveAll(e => e == null) — чистка після Destroy.
Відповідь на 30 секунд: Гра стартує через TDGameBootstrap. Логіка в GameManager. Башні на BuildZone, вороги по шляху з LevelMap (BFS). Башні стріляють через Projectile. HP кристала в GameManager. Після 4-ї хвилі — випадкова нагорода. Баланс — GameConfig.

Частина 2. Константи, масиви та MonoBehaviour

1. Константи (const)

Константа — значення, задане один раз і не змінюється під час гри.

public const int StartingGold = 120;
public const int WavesPerLevel = 10;
public const float SellRefundRate = 0.7f;
ЧастинаЗначення
const«Не змінювати»
intЦіле число
floatДробове (0.7f)

Навіщо: усі числа в GameConfig — змінив у одному місці, працює скрізь.

У грі: Gold = GameConfig.StartingGold → старт з 120 золота.

public const int StartingGold = 120;  // не змінюється
public int Gold = 120;              // змінюється при покупці

2. Масиви ([])

Масив — список значень одного типу з індексами 0, 1, 2...

public static readonly string[] TowerNames =
{
    "Лучник", "Гармата", "Мортира", "Крижана", "Блискавка", "Снайпер"
};
public static readonly float[] RaceRate = { 1.15f, 1f, 1f };
ІндексTowerNamesRaceRate
0Лучник1.15 — ельфи (+15% швидкість)
1Гармата1.0 — гноми
2......

Звернення: TowerNames[0] → «Лучник»; RaceRate[(int)RaceType.Elves] → 1.15

enum + масив: Archer=0, Cannon=1... тому (int)type — номер у масиві.

3. MonoBehaviour

MonoBehaviour — базовий клас Unity для скриптів на об'єктах сцени.

public class GameManager : MonoBehaviour  // є в сцені
public static class GameConfig { ... }    // НЕ MonoBehaviour — лише числа
МетодКолиУ проєкті
Awake()Створення об'єктаInstance = this
Start()Перед 1-м кадромМеню, камера
Update()Кожен кадрТаймер, стрільба, рух

Також дає: transform, gameObject, Destroy(), AddComponent(), StartCoroutine().

Приклад разом

// GameConfig — НЕ MonoBehaviour
public const int StartingGold = 120;
public static readonly string[] RaceNames = { "Ельфи", "Гноми", "Орки" };

// GameManager — MonoBehaviour
public class GameManager : MonoBehaviour {
    public int Gold = GameConfig.StartingGold;
    void Start() { _ui?.ShowMainMenu(); }
    public void SelectRace(RaceType race) {
        Gold = GameConfig.StartingGold;
        _ui?.SetMessage(GameConfig.RaceNames[(int)race]);
    }
}
